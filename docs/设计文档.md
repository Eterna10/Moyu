# Moyu 设计文档

> Moyu 是一款对标 Typora 的「所见即所得」Markdown 桌面编辑器，基于 Electron 构建，所有代码与资源均可离线运行。

## 1. 设计目标

| 目标 | 说明 |
| --- | --- |
| 所见即所得 | 文档默认以排版后的效果展示；点击任意段落即可就地编辑该段落的 Markdown 源码，离开后立即重新渲染（块级实时渲染，与 Typora 的块焦点模式一致）。 |
| 纯文本为唯一真相 | 编辑器内部始终以 Markdown 字符串作为唯一数据源，渲染结果只是视图，保证文件不会被「改写格式」。 |
| 沉浸写作 | 无工具栏的简洁界面、专注模式、打字机模式、可隐藏侧边栏、全屏。 |
| 完整的 Markdown 生态 | GFM 表格 / 任务列表 / 删除线、代码高亮、KaTeX 数学公式、Mermaid 图表、脚注、目录 `[TOC]`、YAML Front Matter、`==高亮==`。 |
| 本地优先、安全 | 不依赖网络；渲染结果经 DOMPurify 净化，渲染进程开启 `contextIsolation` + `sandbox`，Markdown 中的脚本无法执行。 |

## 2. 界面设计

```
┌───────────────────────────────────────────────────────────────┐
│ 文件  编辑  段落  格式  视图  主题  帮助          (原生菜单栏) │
├──────────────┬────────────────────────────────────────────────┤
│ [文件] [大纲] │                                     ┌──查找───┐ │
│              │        # 文档标题                     │ 替换    │ │
│  ▾ notes     │                                     └─────────┘ │
│    a.md      │        正文段落（渲染态）                         │
│    b.md      │        ┌──────────────────────────────┐          │
│              │        │ **正在编辑的段落源码**（高亮） │ ← 编辑态 │
│  侧边栏       │        └──────────────────────────────┘          │
│  (可拖拽宽度) │        表格 / 公式 / 图表 ……                     │
├──────────────┴────────────────────────────────────────────────┤
│ ☰  </>  专注 打字机            字数 1,024 · 字符 3,200 · 已保存 │
└───────────────────────────────────────────────────────────────┘
```

* **原生菜单栏**：所有功能都可通过菜单与快捷键访问（与 Typora 快捷键保持一致）。
* **侧边栏**：「文件」页签显示打开的文件夹树，可新建文件；「大纲」页签根据标题实时生成，点击跳转，滚动时高亮当前章节。
* **写作区**：居中排版，宽度可配置；文档末尾预留半屏空白，便于打字机模式。
* **状态栏**：侧边栏 / 源码模式 / 专注 / 打字机 开关，字数统计（中文按字、英文按词）、阅读时长、保存状态。
* **查找替换浮层**：支持区分大小写、正则表达式，匹配项在渲染视图中高亮。
* **主题**：GitHub（默认）、Newsprint（报刊）、Night（夜间）、Midnight（午夜蓝）四套主题。

## 3. 功能规划

### 3.1 编辑
* 块级实时渲染：点击渲染块进入编辑，光标位置按「渲染文本 → 源码」映射算法定位到点击处。
* 编辑块内 Markdown 语法高亮（标记符号淡化、标题/代码/公式着色），标题块按对应字号显示。
* 公式、图表、表格、HTML、图片等块在编辑时下方显示实时预览。
* 智能回车：段落拆分；列表 / 任务列表 / 引用自动续写，空项回车退出；表格回车新增一行；输入 ```` ```lang ```` 或 `$$` 回车自动补全闭合标记。
* 方向键跨块移动、空块退格删除、相邻段落退格合并、Tab / Shift+Tab 缩进。
* 全局撤销 / 重做（跨块，按输入节奏合并历史）。
* 任务列表复选框在渲染态直接点击切换。
* 源代码模式（Ctrl+/）：整篇源码编辑，与所见即所得模式互相定位光标。
* 图片：插入时按规则复制到指定目录或通过 PicGo (app) / PicGo-Core / 自定义命令上传图床；支持 YAML `typora-copy-images-to`、批量上传本地图片、上传失败回退本地。

### 3.2 文件
* 新建、打开、保存、另存为、打开文件夹、最近文件、新窗口。
* 自动保存（可选）、外部修改检测、关闭前未保存提示、保持原文件换行符（LF / CRLF）。
* 命令行 / 文件关联打开、单实例。
* 导出 HTML（独立文件，内联样式）与 PDF。

### 3.3 视图
* 侧边栏、大纲、文件树、专注模式、打字机模式、全屏、缩放、主题切换。

### 3.4 偏好设置

参考 Typora、Obsidian、VS Code 的同类选项，分为 7 个分栏，修改即时生效并同步到其它窗口，可一键恢复默认（保留最近文件、窗口位置、插件启用状态）：

| 分栏 | 选项 |
| --- | --- |
| 通用 | 启动时打开的内容、最近文件数量、自动保存 / 延迟、失去焦点时保存、外部修改处理、新建文件换行符、保存时补全末尾换行、保存时删除行尾空格 |
| 外观 | 主题、正文字体（仅作用于文档区）、字号、行高、段落间距、版心宽度、首行缩进、标题自动编号、状态栏 / 字数显示、侧边栏位置 |
| 编辑器 | 回车键行为、自动配对括号与引号（含输入法全角符号）、选中包裹、实时预览、拼写检查、Tab 宽度、空格 / 制表符 |
| Markdown | 语法扩展开关（单换行、自动链接、智能标点、公式、高亮、上下标、Mermaid）、代码块行号与换行、公式编号、插入时使用的列表 / 加粗 / 斜体符号 |
| 图像 | 插入规则、路径语法、上传服务 |
| 导出 | 导出主题、导出后打开、HTML 嵌入图片、PDF 纸张 / 方向 / 页边距 / 页眉页脚 |
| 插件 | 启用 / 停用、错误信息、插件目录 |

实现要点：标题编号与公式编号在解析整篇文档时写入 `data-num` / `data-eq` 属性（编辑器按块渲染，跨块的 CSS 计数器无法连续）；排版类选项以 `<body>` 类名 + CSS 变量实现，导出时写入同样的类名与变量，保证所见即所得。

### 4.1 编辑器核心模型

1. 文档 = 一个 Markdown 字符串 `text`。
2. 每次提交时用 markdown-it 解析，取顶层 token 的 `map`（行区间）切分出「块」，未被 token 覆盖的非空行（脚注定义、链接引用定义）作为 `raw` 块。
3. 每个块独立渲染并按 HTML 内容复用 DOM 节点（避免 Mermaid / 图片重复渲染闪烁）。
4. 激活块时，用「行区间 [start, start+len)」描述编辑范围，用高亮文本框替换该块；输入时只做 `prefix + value + suffix` 拼接，不重新解析整篇文档。
5. 离开块（点击别处、方向键、Esc、回车拆分）时提交：重新解析、渲染，必要时清理空块。
6. 撤销栈保存 `{text, active, selection}` 快照；`beforeinput` 时记录，1 秒内的连续输入合并为一步。

### 4.2 插件架构

```
主进程 plugins.js                        渲染进程 plugins.js（PluginHost）
 扫描 内置 plugins/ + %APPDATA%\Moyu\plugins
 读取 plugin.json、启用状态   ──列表──▶  逐个以 <script> 加载入口 → Moyu.definePlugin(def)
 插件数据 plugin-data/<id>.json ◀─存储─▶  def.activate(ctx)   ctx = 命令 / markdown / editor / workspace / ui / storage
 「插件」菜单 ◀──────────命令列表─────── ctx.commands.register
 菜单点击 ────────plugin:<id>:<cmd>────▶  执行插件命令
```

* **扩展点**：markdown-it 插件、自定义代码块语言、渲染后处理（`md.js` 中的注册表，`editor.rebuildMd()` 重建解析器）；命令 + 快捷键；状态栏项；侧边栏页签；事件总线（open / change / willSave / save / theme）；模态框与输入框；插件私有存储。
* **可撤销**：插件通过 `ctx` 注册的每一项都会记录清理函数，停用或重新加载时按逆序撤销，无需重启。
* **隔离**：脚本语法错误、`activate` 异常或超时（5 秒）只标记该插件「加载失败」并在管理页显示原因；宿主对插件回调统一 try/catch。
* **冲突处理**：插件快捷键与内置快捷键或其它插件冲突、或格式非法时忽略该快捷键；同 id 插件只加载一个（内置优先）。
* **权限**：插件运行在渲染进程，与编辑器界面同权限（不能直接访问 Node），插件输出的 HTML 同样经过 DOMPurify。

### 4.3 安全

* `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`。
* 所有渲染 HTML 经 DOMPurify 过滤（允许 `file:` 图片协议）。
* 外部链接只允许 `http/https/mailto`，通过系统浏览器打开；禁止页面导航与新窗口。
* CSP 限制脚本来源为本地文件（应用自身与插件目录）。

### 4.4 背景图片的自动透明度

背景图片之上叠加一层与主题背景色相同的遮罩，遮罩的不透明度 `a` 由图片自动计算：

1. 把图片缩放到 48×48，计算每个像素的相对亮度 `L`、平均值与标准差 `σ`（复杂度）。
2. 读取当前主题背景色的亮度 `Lb`，计算图片与背景的平均亮度差 `d = mean(|L − Lb|)`。
3. `a = clamp(1 − 0.12 / (d + 0.6σ), 0.45, 0.94)`：图片越接近主题底色、越平坦，遮罩越淡；反差越大、越花哨，遮罩越浓，使文字区域的有效背景始终接近主题底色。
4. 切换主题时用新的 `Lb` 重新计算，因此同一张图在浅色与深色主题下都清晰可读。

强调色取自图片中饱和度最高的色相区间（按饱和度加权平均），再按主题明暗调整亮度以保证对比度。

### 4.5 工作区功能（`src/main/workspace.js`、`src/renderer/js/workspace.js`）

- **右键菜单**：主进程把 Chromium 的 `context-menu` 事件（含拼写建议与可用的编辑操作）转给页面；页面按点击位置（编辑区 / 链接 / 图片 / 文件树 / 输入框）组装菜单项，再请主进程用原生菜单弹出，返回被点击项的 id。在渲染好的块上点右键会先把光标放到该处，表格操作因此知道作用于哪个单元格。
- **表格操作**：直接改写表格的 Markdown 源码（按 `|` 拆分成行列再重新拼接），源码编辑与纯文本模式共用；纯文本模式下操作完成后把光标放回目标单元格。
- **智能粘贴**：剪贴板中的 HTML 先做归一化（样式表示的加粗 / 斜体转为标签、去掉包裹块级内容的行内外壳、压平单元格中的块级内容、KaTeX 取回 TeX 源码、保留代码块语言），经 DOMPurify 只保留认识的标签后，交给纯文本模式的 HTML → Markdown 序列化器；无法可靠转换时退回纯文本。代码块、公式块、表格中始终粘贴原样文字。
- **文件夹内搜索**：主进程遍历文件夹（跳过隐藏目录、超过 2 MB 的文件，最多 3000 个文件 / 500 处匹配），按文件的实际编码解码后逐行匹配，返回带上下文的摘要。
- **崩溃恢复**：文档有未保存的修改时，页面在停止输入 1.5 秒后把全文写入 `%APPDATA%\Moyu\recovery\<窗口标识>.json`（先写临时文件再改名）；保存、内容清空或正常关闭后删除。启动时若还有不属于任何运行中窗口的文件，说明上次没有正常退出，列出供恢复或丢弃。
- **阅读位置**：滚动停止后记录 `文件路径 → scrollTop`（最近 200 个，保存在设置中），打开文件时恢复。

### 4.6 标签页

每个标签页是一份文档。当前标签页的状态就在 `state` 与编辑器里；其余标签页的状态（文本、已保存的文本、换行符、修改时间、撤销 / 重做记录、光标、滚动位置）存放在各自的对象中，切换时把当前的换出、目标的换入，因此只有一个编辑器实例，插件接口也不需要改动——切换标签页对插件而言就是一次「打开文档」。

- **打开文件**：已经打开的切换到它所在的标签页；否则在当前标签页之后新建一个（当前是空白文档时直接复用）。`force` 表示从磁盘重新载入当前文档。
- **切换**：按顺序串行执行；开着自动保存时先保存；切换后检查文件是否被其它程序改动。
- **关闭**：有未保存修改时先切换过去并询问；关闭窗口前逐个确认。最后一个标签页关闭后换成空白文档。
- **改名 / 删除**：文件或其所在文件夹被改名、删除时，所有打开着它的标签页一并处理。
- **崩溃恢复**：每个标签页有自己的恢复标识，后台标签页内容不变，只写一次。
- **会话**：记录打开着的文件与当前文档；「启动时重新打开上次的文件」会恢复全部标签页，只有当前的那个立即渲染。
- 关闭「在标签页中打开文档」后，打开文件改为替换当前文档（先询问未保存的修改）。

### 4.7 导出图片与 Word

- **长图**：复用导出 PDF 的 HTML，在隐藏窗口中渲染后截图。截图的像素密度跟随显示器缩放，因此用「窗口宽度 + 页面缩放」得到想要的输出宽度（版面宽度 × 清晰度）；该窗口使用独立的会话，缩放比例不会波及主窗口。单张截图超过约 16000 设备像素会失败，所以按 12000 像素分段，分段点取在顶层块的边界上；页面自身的脚本用 CSP 禁止，测量与滚动的代码由主进程注入。
- **Word / ODT / RTF / EPUB / LaTeX**：把 Markdown 源码交给 Pandoc（`commonmark_x`，关闭 Moyu 没有的扩展语法，按设置启用硬换行与上下标），`==高亮==` 预先换成 `<mark>`，`[TOC]` 换成 Pandoc 的目录。Pandoc 按「设置中的路径 → PATH → 默认安装位置」查找，找不到时给出安装说明。

### 4.8 在线更新

每次启动（或 `帮助 → 检查更新`）调用 GitHub API `repos/Eterna10/Moyu/releases/latest`，状态显示在状态栏，发现新版本时弹窗（立即更新 / 跳过此版本 / 取消）。下载以流式写入临时目录，同时计算 SHA-256，并与 GitHub 提供的 `digest` 比对；大小或校验值不符时删除文件并报错。

**增量更新（安装版）。** 安装后的 Moyu 约 367 MB，其中 Electron 运行环境占绝大部分且很少变化，Moyu 自身的代码只有 `resources/app.asar`（约 9 MB）。`npm run dist` 会额外生成 `Moyu-<版本>-app-electron-<Electron 版本>.asar.gz`（约 4.5 MB）。检查更新时，若发布中有这个文件、其中的 Electron 版本与本机一致、且 `resources` 目录可写，就优先下载它：

1. 校验 SHA-256 后解压，直接解析 asar 头部读取其中的 `package.json`，确认是 Moyu 且版本号与发布一致，再写为 `resources/app-update.asar`；
2. Moyu 正常退出后，用 `Moyu.exe` 以 Node 模式（`ELECTRON_RUN_AS_NODE=1`）运行辅助脚本：等待原进程结束，把 `app.asar` 改名为 `app.asar.old`、`app-update.asar` 改名为 `app.asar`（失败时改回原名并重试，最终仍失败则保留旧版本），再通过 `Start-Process` 以原来的启动参数重新打开 Moyu（经 ShellExecute 启动，新进程不会继承旧进程的句柄）；
3. 下次启动时清理残留的 `app-update.asar` / `app.asar.old`。

更新包内容无效时，对话框改为提供完整安装包。便携版每次运行都从自身解压，无法只替换其中一部分，始终下载完整文件。**发布时**：如果某个版本改动了 `app.asar` 以外的内容（Electron 版本、文件关联与图标、安装程序设置等），不要上传 `.asar.gz`，用户会自动改为下载完整安装包。
